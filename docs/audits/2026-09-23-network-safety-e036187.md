# Targeted network Safe Apply / recovery review

Reviewed baseline: `e03618713f4737e5518e857e229c25a7ef5a2275`, branch
`V1 UI qualification branch`. The remediation commit containing this report is the
final reviewed source state. Scope: network ownership, scoped artifacts and

UI and DV07 were not changed; no full backend regression or live deployment.

## Outage attribution

The reported outage preceded deployment of c37cd53/e036187. The VM was reported
to be running older post-e9bc9d0 binaries. This review does **not** attribute

not a retrospective explanation of the outage.

## High findings

1. **OPEN — networkd does not load the candidate or restored file contents.**
   `runNetworkdReconfigure` executes only `networkctl reconfigure <name>`.
   [systemd 257's own contract](https://raw.githubusercontent.com/systemd/systemd/v257/man/networkctl.xml)
   explicitly distinguishes reconfiguration from reloading edited profiles.
   The command uses the daemon's loaded configuration; the current inventory
   checks observe profile path and administrative state, not loaded bytes or
   resulting addresses/MTU. A configured old profile can pass those checks.
   Private routes may appear correct because the separate route executor
   already installed them, which does not validate networkd's cached intent.
   The same defect affects rollback: restored files do not prove restored
   daemon state. A later unrelated reload can activate disk state at a different
   time. Per-link command arguments alone do not prove isolation across daemon
   dependencies, nor new-configuration convergence.

   **Remaining remediation:** qualify a supported profile-refresh strategy on
   the actual networkd version, preserving external eth0 ownership and bounding
   all affected links. Verify address/route/MTU results independently for Apply
   and Restore and repeat after restart. Do not simply restore a blind global
   reload or claim a mocked reconfigure proves this. No speculative manager
   changes were introduced in this review.

2. **FIXED — guard release always failed after an otherwise successful undo.**
   c37cd53 constructed a chain-only `NFTSnapshot`; validation requires a complete
   table snapshot, so `DeleteBatch` failed before executing nft. Furthermore,
   ordinary Restore already recreates the exact before-table without the guard;
   deleting an absent chain is not an idempotent nft operation. The host method
   now returns successfully on absence, validates an existing barrier, deletes
   only that fixed chain, and verifies the remaining table. A real isolated
   nft kernel regression covers repeated release, empty-table undo, and a
   subsequent guard installation.

3. **FIXED — restart fabricated rollback after recovery failure.**
   `safeapply.Open` cleared `RecoveryRequired` with a rolled-back receipt without
   running undo or verification. That lost evidence and could admit work while
   a guard or partial configuration remained. Startup now executes durable undo
   and verification, preserving pending recovery on failure. Tests cover both
   repeated failure and successful recovery; no synthetic success is recorded.

4. **FIXED — scope isolation did not cover all recovery/route entry points.**
   External-interface admission compared interface fields only; a top-level
   route could put external eth0 into the rendered-artifact change set.
   Scoped command resolution accepted externally-managed enrollment entries.
   Boot undo rewrote the full before-artifact set, including unchanged legacy
   management profiles. Route-derived external mutations now fail admission
   and recovery; the full scoped command set is validated before any command;
   boot undo writes only the transaction's changed artifacts. A real-file
   inode/mtime regression proves repeated boot undo leaves an unchanged external
   profile untouched. Restart also reconstructs the verification scope.

5. **FIXED — scoped recovery rejected an owned failed/configuring profile.**
   Restore used normal Apply admission requiring `configured`, so failures
   needing reconfiguration could not recover. The separate scoped-restoration
   entry tolerates transient/failed state only for its selected owned links,
   retaining name/profile/drop-in checks and refusing foreign profiles. The
   daemon cache-refresh blocker in finding 1 remains independently open.

6. **FIXED — empty first-boot baseline still invoked global reload.**
   The new baseline has no owned profiles, but `persistBaselineArtifacts`
   unconditionally invoked manager-wide `networkctl reload`. It now returns
   without filesystem or manager operations when rendering no profiles. A
   Linux-root entry-path test intercepts networkctl and proves no invocation.

No Critical defect is claimed by this review.

## Guard and asynchronous lifecycle

| Path | Actual behavior / verdict |
| --- | --- |
| Capture | Observes before-state; does not install the guard. Existing reserved guard refuses a new transaction. |
| Apply in progress | Installs barrier before route/rule mutation and retains it through composite verification. |
| Awaiting confirmation | Final normal firewall Apply removes barrier before returning; candidate remains uncommitted. |
| Confirm | Re-verifies candidate and commits journal; does not need a second guard release. |
| Explicit rollback / failed Apply / timeout | Fresh bounded rollback context; barrier stays during undo; exact before-firewall is restored last. Absent-guard release now succeeds. |
| Failed undo | Recovery-required is retained; a barrier may intentionally remain while runtime is unknown. Never delete the whole table manually as an automatic remedy. |
| Startup | Pending undo is retried and verified; no discard of recovery-required evidence. Pre-networkd artifact undo has the same changed-link write scope. |

Engine status reconciliation updates its journal from Agent outcomes; it does
not itself reconfigure interfaces. The controller serializes Apply, Confirm,
Rollback and timeout with a mutex. These do not establish a daemon-side fence
for asynchronous networkd work: finding 1 prevents a claim that delayed daemon
activity and restored configuration are fully qualified. Empty first-boot
startup no longer invokes a global reload; nonempty baseline support is not a
replacement for qualified scoped activation.
