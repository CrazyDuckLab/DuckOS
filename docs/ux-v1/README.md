## Design authority and scope

Keep the ten established Full-mode areas. Add stable second-level routes, contextual object links and local command/search navigation, not a larger permanent sidebar. Dashboard and topology have normal homes under System and Logs / Diagnostics respectively; the brand/home link provides a shortcut without creating a conflicting taxonomy.

These documents design the requested product, including carrier/enterprise capabilities, while explicitly distinguishing current public API behavior, internal components, and contract gaps. A discoverable page is not an enabled feature promise. No unavailable function may generate fake production state.

The latest visual direction intentionally supersedes blanket exclusions of mascot imagery on login/onboarding: a tasteful glasses mascot is optional there, never a permanent Full-mode ornament. The existing compact ASCII duck remains the primary navigation/CLI identity. Mountains are a subtle brand layer, not a reserved obstruction over tables. No image asset is generated by this specification.

## Coverage method

Each page has all 44 requested dimensions. Reusable behavior is specified once in the interaction system and restated explicitly in each page contract where it affects operations. Feature names map to pages, including unusual families. Helper-only packages map to the product surfaces they support rather than acquiring artificial settings pages.

The proposed route catalog does not constitute new REST endpoints. API and CLI equivalents must come from verified reachable contracts. Model-only operations remain unavailable with a specific explanation until backend integration is complete.

The A–T walkthroughs are analytical design rehearsals, not tests with recruited participants and not browser/runtime test results. Their click counts are defined estimates. Usability and visual-regression execution remain acceptance work for implementation.
