# Easy, Full and first-run experience

## Full workspace

Primary jobs: inspect many related objects, edit precisely, preview risk and diagnose quickly. The ten-area navigation and 99-page catalog are stable. Full forms expose all supported advanced fields and generated artifacts; ordinary operations never require a Linux console. Show CLI teaches the same DuckOS object model.

Default home has compact factual rows: node/uptime/time trust; current WAN layers; active incidents; pending transaction; interface errors; resources; relevant traffic; meaningful recent changes. Unknown metrics stay absent/unknown with explanation rather than receiving decorative zeroes. Allow panel choice and saved views. No greeting or marketing sentence.

At 1920 px show list and inspector. At ultrawide, add useful columns and compare/evidence panes rather than expanding whitespace. Do not create infinite horizontal stretches of small cards. Focus can stay in a table for hours while background evidence updates.

## Easy workspace

Easy centers on intentions and outcomes, not a filtered Full menu. Home answers what works, what is wrong, which connection is active and where to act. Internet shows layered probes. Networks combines LAN/VLAN/ports/DHCP/DNS/access/Wi-Fi. Devices combines identity and access. Publish combines service exposure. Care combines maintenance/recovery.

Beginner forms use plain language and suggest a safe path; suggested defaults are shown in the review. Do not imply that “Guest” automatically secures every route, L2 switch, VPN or IPv6 path. Explain the enforcement scope and unknown hardware constraints.

The same objects retain all advanced state. A pre-existing custom BGP policy remains untouched when someone changes the page theme, creates a simple guest network, or switches modes. A supported simplification edits only selected fields and previews downstream changes. No implicit full-tunnel access.

## First-run state machine

Registration means a local administrative account, not a cloud account. Branding is local and optional; no external image/font/network requirement. Each step has Back, Help, saved non-secret progress and an explicit reason for any blocked next action.

1. Welcome: language EN/RU/DE/ES, appearance Light/Dark/System. Explain local-first briefly. Technical protocol tokens stay canonical.
2. Establish local Owner: installation enrollment authority, username/password and supported authentication requirements. Uniform login errors, no secrets in drafts/history. Do not fabricate MFA if unsupported.
3. Detect environment: architecture, virtualization, usable NICs and capability evidence. Choose Router/Gateway, Server/Single-interface or Advanced/Custom. Suggest, do not force. One NIC is valid; no mandatory LAN.
4. Protect current management: show actual interface/address/source path and known recovery options. If evidence is insufficient, keep existing networking and restrict network changes. Do not mark management safe because loopback health works.
5. WAN intent: connection type, interface, addressing, DNS, credentials, auto MTU/manual, health checks. MAC hardware/configured/effective are shown. Clone-current requires observed local-client identity; otherwise guided selection/manual.
6. LAN intent, only if desired: network name, subnet, port membership/tagging, DHCP, DNS, IPv6 and isolation. A server can skip creating LAN without error.
7. Access intent: router management exposure, peer/client isolation, selected network access. Show generated dependencies and fail-closed fallback. Optional services/tunnels are not mandatory onboarding chores.
8. Time and trust: show clock trust separately. Offer local/trusted time setup where available. TIME_UNTRUSTED explains effects on certificates, expiration and signed-update validation. No fake current date.
9. Real tests: link → addressing → gateway → DNS → Internet; IPv4 and IPv6 separate. Show source/target/time and What failed / What still works. Offline setup is allowed; label “Local management ready; Internet not verified.”
10. Review: all objects, generated ownership, base revision, risk, current management dependence and verification requirements.
11. Safe Apply for network changes: authoritative phases/deadline, persistent confirm/rollback, recovery on reconnect. If mutation API is unavailable, stop at review with a specific backend gap; do not substitute a simulated success wizard.
12. Choose initial Easy/Full; save only preferences. Completion summarizes verified results, remaining issues and useful next actions.

Optional glasses mascot appears at welcome/login/completion. A celebratory connectivity result requires actual successful probes; offline readiness gets neutral copy, not an “Internet freedom” success claim. Animation never signals whether an entered username exists. Reduced-motion has static equivalents.

## Single-interface / server workflow

Preserve the existing management address/default route unless explicitly changed with validated recovery. Router-origin management is distinct from forwarded traffic. Primary tasks: firewall, routing, VPN/proxy clients, subscriptions, certificates, reverse services, updates and monitoring. LAN not created is intentional. Adding a second NIC later is an interface role-assignment workflow, not reinstall.

An advanced user can choose a custom profile and inspect all defaults before applying. The UI distinguishes protecting the host itself from forwarding between networks. A public listener's exposure review is especially important on a single public NIC.

## Task continuity

A user can start in Easy, inspect generated rules in Full, and return without losing draft fields. A shared candidate strip identifies edits made by any current interface. Show mode-specific presentation, never separate configuration copies. Undo draft is not rollback of a committed config.

Support local browser settings when account preference API is unavailable, clearly labeled “This browser only.” No secrets or networking configuration in preference storage. Resetting layout does not reset device configuration.

## Future implementation acceptance

- Owner can finish local setup without Internet/cloud availability.
- Server profile never blocks for missing LAN/radio.
- A mismatched management path blocks mutation and explains evidence.
- Offline completion and fully verified Internet success are distinct.
- Mode changes generate zero network-write requests.
- Invalid/unsupported advanced configuration survives untouched.
- All four locales and both themes complete the flow without clipped warnings.
- Login errors and animation do not reveal account existence.
