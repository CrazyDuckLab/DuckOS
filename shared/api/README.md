# Shared observation API v1

`overview.schema.json` is the wire schema; `types.ts` is generated by
`node scripts/schema.mjs`. `make check` verifies it is up to date and checks Go
model compatibility. API and IPC use the same versioned observation envelope.

- `GET /api/v1/health`: unauthenticated process liveness, no host facts.
- `GET /api/v1/ready`: bearer authentication, verifies Agent communication.
- `GET /api/v1/overview`: bearer authentication, Engine-mediated observation.
- `GET /agent/v1/overview`: Unix socket only, Linux peer UID authentication.

These observation endpoints accept no query/body and perform no host mutation.
Local [identity](identity.md), [network preview](network-preview.md) and
[offline flow simulation](network-simulation.md) have separate authenticated
contracts. Errors are JSON and
do not contain raw command stderr, tokens or file contents. Unknown API routes
are errors, not the SPA entry point. Transport error HTTP 503 differs from a
successful partial observation with `issues`. Consumers must show collection
time, mark stale retained observations after refresh failure, and treat metrics
with a matching component issue as unavailable. First CPU sample can be null.

DNS describes resolver configuration, not successful resolution. Routes include
IPv4/IPv6 tables. nftables counts summarize loaded objects without returning
ruleset contents or claiming a security score. Service status is allowlisted.
See ADR-0005 for identity, limits, management exposure and remaining work.
