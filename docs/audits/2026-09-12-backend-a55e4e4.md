# DuckOS V1 — independent backend audit

Date: 2026-09-12. Scope: backend, public API, Duck CLI, privileged runtime,
security and recovery. No UI work, new features, remote host access or deployment.

## 1. Audited HEAD

Branch: `V1 UI qualification branch`.
Baseline: `a55e4e4b9556b08ec9226e084eaf5328b272f265`.
The working tree was clean at the start. HEAD was not reset or changed.
Fixes and regression tests described below are uncommitted working-tree changes
on that baseline; they are not claims about the unchanged commit itself.

Existing QA/evidence and gap documents were references, not proof of runtime
completion. Inspection followed executable composition roots and call sites,
not only exported types or successful tests. This is a risk-prioritized audit,
not a proof that every line or possible execution has been verified.

## 2. Critical findings

No remotely reachable Critical exploit was demonstrated. This does not mean
the backend is safe to freeze. In particular, the destructive release-ID defect
below is High in its current, not-publicly-connected library context; it must
not be described as demonstrated remote root access.

## 3. High findings

### H01 — Configuration handler bypassed authentication and exposed raw revisions

Evidence: [API dispatch](../../internal/api/server.go),
[configuration handler](../../internal/api/config.go),
[configuration DTOs](../../internal/engine/config.go).
The dispatcher enters the config handler before the normally authenticated API
handler. The baseline config handler did not authenticate or authorize requests.
Its status serialized arbitrary configuration from current/history/pending
revisions, including any secrets in that configuration.

Reachability qualification: the shipped API composition root does not enable
this journal; it currently returns unavailable. The defect becomes exploitable
when the advertised journal surface is enabled, so it is a freeze blocker, not
evidence of an active anonymous production mutation.

Fixed: explicit session/permission checks; bootstrap observation only before
enrollment; replacement of bootstrap access after enrollment; secret-safe
revision summaries; bounded request-reader errors propagated. Config errors no
longer reflect arbitrary Engine error strings. Confirm/rollback IDs now dispatch
correctly rather than matching an unreachable switch case.

### H02 — Generic configuration transactions reported Linux success without Linux

Evidence: [generic config coordinator](../../internal/engine/config.go), compared
with [real networking coordinator](../../internal/engine/network_control.go).
Baseline Prepare advanced the journal to awaiting confirmation without invoking
Agent. Confirm committed only the journal; rollback only changed that journal.
There was no corresponding Linux apply, verification, timeout worker or
authenticated receipt reconciliation. Validation also claimed success without
domain validation. Request correlation was not a durable idempotency contract.

Contained: generic mutations, candidate validation/diff and reconciliation now
fail closed with `ErrConfigRuntimeUnavailable`; status advertises no unsupported
actions. The real networking implementation was retained. Connecting it to the
public contract remains an unresolved software blocker, not a new feature added
by this audit. Tests that treated journal transitions as Linux evidence were
replaced with explicit fail-closed tests; real networking/Safe Apply tests remain.

### H03 — Safe Apply could confirm after its deadline

Evidence: [Controller.Confirm](../../internal/safeapply/controller.go).
Confirm checked the deadline before a potentially slow verification, but not
afterwards. A verification spanning the monotonic deadline could still commit.
Fixed: recheck monotonic and absolute deadlines after verification and perform
rollback on expiry. A deterministic regression makes verification cross the
deadline and checks restoration rather than successful confirmation.

### H04 — Privileged QoS mutation lacked the network safety boundary

Evidence: [Agent composition](../../cmd/duck-agent/main.go),
[QoS host](../../internal/agent/qos_host.go), [QoS package](../../internal/qos).
Production startup enabled a controller accepting raw tc argument plans without
the enrolled-interface ownership, management-path protection, durable before
state or restart-safe rollback used by the guarded networking path. Partial
failure and rollback results did not establish restoration of connectivity.
This is not a demonstrated shell-injection exploit: arguments are executed
without a shell, but an unrestricted privileged tc plan is still unsafe.

Contained: production QoS mutation service is not enabled and reports
unavailability. Regression pins that gate. Typed/guarded transactional integration
is still required before re-enabling it; internal QoS code is not certified safe.

### H05 — CLI could transmit credentials over remote HTTP or redirects

Evidence: [CLI transport](../../cmd/duck/main.go).
`--allow-insecure` permitted non-loopback HTTP, and the default HTTP client
followed redirects. Same-host redirects can forward credentials to a different
port/service. Fixed: HTTP requires explicit opt-in and a literal loopback IP;
URLs must be origins without userinfo, query or arbitrary paths; redirects are
refused. Added response overflow rejection and JSON Content-Type for bodies.
HTTPS continues to use certificate verification. Regression covers transport
selection and refusal to follow redirects.

### H06 — Release IDs and activation could select or remove unsafe paths

Evidence: [release storage](../../internal/upgrade/storage.go).
Baseline accepted `.` and `..`; Remove joined the ID to its root and recursively
removed that result. Reserved anchor names were accepted as releases. Activate
accepted incomplete/tampered directories, unlinked Active before creating its
replacement, and did not establish durable directory changes. Free-space reporting
was a constant rather than filesystem capacity.

Reachability: internal update storage, not an exposed production mutation route.
No dangerous recursive deletion was executed during reproduction.

Fixed: canonical child IDs excluding dot/parent/anchor names; owned private real
store directory; regular-file and digest checks before activation; exclusive
materialization, file and directory synchronization, atomic symlink replacement,
real capacity/time metadata, and serialization within one ReleaseStore instance.
Tests reject bad IDs and incomplete/tampered/symlink candidates while retaining
the previous Active anchor. This does not make the entire update transaction
crash-consistent; see H11.

### H07 — Package/preflight and health gates could panic or falsely pass

Evidence: [package decoder](../../internal/upgrade/package.go),
[preflight/orchestrator](../../internal/upgrade/orchestrator.go),
[health executor](../../internal/upgrade/healthcheck.go).
Short packages panicked before header validation. The external release arch was
checked without binding the signed manifest architecture. Missing health runners
and empty check lists could report success. Concurrent operations could change
Active between activation and verification/rollback.

Fixed: short/trailing envelope rejection, signed architecture/target binding,
channel consistency and capacity accounting; invalid verification-key lengths
are rejected rather than passed to a panic-prone verifier. Removed the incorrect
comparison of source version to the target release version. Missing health
setup fails before activation; activation/verification/rollback is serialized.
Regressions cover parser lengths, wrong signed architecture, absent health
checks/runner, unchanged activation on invalid setup and the verification lock.
Source-version/schema migration compatibility remains unresolved (H11).

### H08 — Provisioning redemption ignored scope and node binding

Evidence: [provisioning Store](../../internal/provisioning/provisioning.go).
Possession of a valid credential was sufficient to consume it without enforcing
its declared node or scope. Key derivation used concatenated hashing rather than
the claimed HMAC construction.

Fixed: scope/node-aware atomic redemption, constant-time comparison, expiry and
single-use checks, HMAC derivation. The legacy node-enrollment entry point cannot
redeem node-bound or service-binding credentials. Tests reject wrong scope/node,
legacy bypass and replay. An authenticated caller must supply the node identity;
a self-asserted request field is not a trusted binding. Production enrollment
wiring and durable replay state are still not established by this in-memory Store.

### H09 — Session continuity helpers bypassed idle-expiry policy

Evidence: [session continuity](../../internal/identity/session_continuity.go).
Touch and Renew used direct map access rather than the central session validator;
an idle session could be revived, and renewal could request an excessive lifetime.
These helpers are not mounted as production public endpoints today.

Fixed: both use the central validator and its clock; renewal is bounded by the
normal session lifetime and rotates the token. Regressions cover idle-session
rejection and excessive renewal without destroying a still-valid session.

### H10 — Public contracts and capability declarations are not production-ready

Evidence: [API startup](../../cmd/duck-api/main.go),
[Engine.Config](../../internal/engine/engine.go),
[object listers](../../internal/objectlisters/listers.go),
[CLI network commands](../../cmd/duck/main.go),
[CLI upgrades](../../cmd/duck/upgrade.go),
[CLI backups](../../cmd/duck/backup.go),
[readiness probes](../../internal/chaos/readiness_registry_linux.go).

The startup path does not wire the advertised generic config coordinator,
production domain listers or all export/runtime providers. EnableConfig returns
a Config but does not attach it to Engine.Config. RegisterAll installs unsupported
listers, not actual object collections. Several CLI commands send `/agent/v1/...`
to the public HTTP server, where these are not public API routes; this can become
a static-page response/JSON decode failure. It is broken parity, not a working
private Agent bypass. WireGuard/Xray logical CRUD/export coverage is not supplied
merely by the existence of their packages.

Baseline Linux probes could mark whole features supported from an executable,
module or directory prerequisite. Contained: successful prerequisite-only probes
now report experimental/unverified integration rather than supported. Missing
prerequisite failure states remain visible. A unit test pins this distinction.

Unresolved High blocker: API/CLI method reachability, real collections and stable
revision/action semantics must be completed and tested at the actual startup
composition root before a production UI can rely on them. This cannot be solved
solely by rendering unsupported operations differently in the UI.

### H11 — Update/restore recovery contract is incomplete

Evidence: [orchestrator](../../internal/upgrade/orchestrator.go),
[migration runner](../../internal/upgrade/migrate.go),
[Agent upgrade bridge](../../internal/agent/upgrade_host.go),
[backup package](../../internal/backup),
[Agent backup bridge](../../internal/agent/backup_host.go).

Update state has serialization helpers but no demonstrated durable transaction
tying candidate, Active/Previous anchors, migration and post-restart health to
service activation. The composition exposes status bridges, not a complete
activation pipeline. Signed source/schema compatibility is not bound to the
actual active installation; the migration runner is not that missing guarantee.
Failure of the first activation with no Previous cannot restore a prior release.
Health timeout cannot cancel a CheckRunner that ignores its own timeout, so late
work and goroutine leaks remain possible.

Backup manifests, verification helpers and restore previews do not establish an
integrated encrypted portable archive restore, selective restore, NIC remap,
management-path verification and automatic rollback pipeline. A key-set comparison
called SafeToApply is not evidence that restoring the network is safe.

Unresolved software blocker. Storage/parser fixes are useful containment, not
certification of updates, migrations or disaster recovery. No production update
or restore was attempted.

## 4. Significant Medium findings

- **M01 — Object authentication/RBAC inconsistency.** The objects handler required
  both bootstrap authentication and a session after enrollment. Fixed to use the
  appropriate credential, with a session/bootstrap regression. The per-object
  overlay is still not production-integrated: its key grammar rejects dotted
  kinds and `*`, yet the handler supplies both. There is no demonstrated per-row
  authorization/export policy path. See [objects](../../internal/api/objects.go)
  and [policy](../../internal/identity/policy.go). Do not advertise granular RBAC.
- **M02 — Restore preview mutated its input.** Remap shallow-copied its interface
  slice and modified the original backup. Fixed by copying mutable slices;
  regression confirms preview isolation. [Source](../../internal/backup/restore.go).
- **M03 — Runtime success lacks daemon-level proof.** Xray Apply marshals the domain
  model, checks JSON syntax, assumes signal-based reload, and treats process start
  as success; it does not establish the selected daemon accepts the generated
  configuration. Request-context process lifetime and rollback locking also need
  integration work. This runtime is not connected to public production mutations,
  so no reachable exploit is asserted. FRR, hostapd, RADIUS, ACME and WireGuard
  need actual runtime/provider wiring, not only model tests or binary probes.
  [Xray runtime](../../internal/xray/runtime_linux.go).
- **M04 — CLI cancellation/output contract is incomplete.** Ignored text-output
  write errors and background request contexts do not establish consistent broken
  pipe/cancellation exit semantics. Token-file opening lacks the API loader's
  same-file protection. These are unresolved; standard output and all commands
  have not been certified for scripting. [CLI](../../cmd/duck/main.go).
- **M05 — First-run and runtime evidence freshness.** First-run file helpers do
  not provide the canonical Store's full bounded-read/CAS/durability guarantees;
  startup prerequisite snapshots are not continuous health measurements. These
  helpers must not be promoted to production recovery/readiness contracts without
  integration. [First run](../../internal/firstrun),
  [readiness](../../internal/chaos/readiness_registry_linux.go).

No cosmetic refactoring or low-priority cleanup was undertaken.

## 5. Fixes actually made

Authentication/DTO hardening and honest unavailable config behavior; late-confirm
rollback; production QoS gate; CLI transport hardening; release storage and
package verification hardening; update verification serialization; scoped ZTP
redemption; session continuity policy enforcement; truthful prerequisite readiness;
object-session authentication; non-mutating backup remap previews.

Fail-closed containment intentionally removes false-success paths. It does not
implement the missing public contracts and must not be counted as feature completion.
No UI changes, network-target changes, history rewriting, commit or push.

## 6. Regression tests and verification

Added `audit_regression_test.go` in API, upgrade, Safe Apply, provisioning,
identity, chaos/readiness, backup, Duck CLI and Agent command packages. Updated
configuration tests explicitly distinguish Store receipts from Linux evidence.
Selected tests reproduced failures before fixes (authentication, object sessions,
body limits, short package panic, bad release activation, signed-arch mismatch,
false health success, insecure CLI transport and late Safe Apply confirmation).

Executed locally on macOS with the repository toolchain:

- Baseline full backend/command/integration tests: pass after allowing local test
  sockets. Sandbox socket-denial failures were not classified as product defects.
- Patched `go test -count=1 ./...`: pass.
- `go test -race -count=1` for API, Agent, Engine, state, Safe Apply, identity,
  clientexport, network, upgrade, provisioning, backup, chaos, Duck CLI and Agent
  command: pass. The additional configured-journal and activation-serialization
  regressions were rerun with API/upgrade race tests.
- `go vet ./...`: pass.
- `GOOS=linux go build ./cmd/...` for amd64, arm64 and armv7: pass.
- `git diff --check`: pass.

Cross-compilation is not Linux execution. Passing existing tests is not evidence
that stub observers, journal-only flows or unmounted APIs work end to end. Browser
tests and real Linux daemon/kernel tests were not run for this backend audit.

## 7. Unresolved software blockers

1. Connect one genuine coordinator to public candidate/apply/confirm/rollback,
   with durable request identity, stale revision/concurrent admin handling and
   unknown-result reconciliation through the actual production composition.
2. Supply real domain collections, exported action/capability semantics and
   public methods; repair CLI routes and demonstrate public API parity.
3. Integrate per-object authorization and secret exports at real provider call
   sites; complete durable provisioning replay protection.
4. Replace unsafe QoS mutation enablement only after guarded durable rollback exists.
5. Complete update activation/migration/recovery and protected portable restore
   as durable, verified workflows; do not use helper models as proof of completion.
6. Wire and verify supported daemon integrations, accurate degraded/unknown
   states, cancellable diagnostics/health work and restart recovery.
7. Align installed service permissions and startup with the supported runtime.
   Current [Agent unit](../../packaging/systemd/duck-agent.service) is explicitly
   an internal read-only TEST build with only `/run/duckos-agent` writable;
   [API unit](../../packaging/systemd/duck-api.service) only permits identity
   persistence and loopback networking. These are not production mutable-service
   permissions. Do not simply broaden them to bypass the missing design binding.

These blockers can be progressed in software without first accessing hardware.

## 8. Hardware/credential/network-only blockers

After the software blockers are resolved, a disposable Debian 13 test node with
out-of-band recovery is required for real nftables/iprule/VLAN/DHCP/WAN isolation,
link loss, concurrent administrators, disconnect/timeout/restart and management
path survival. Kernel/network namespace behavior cannot be certified by Mac tests.

Real daemon versions/configuration checks, TLS/ACME credentials and network access,
WireGuard mobile exports, Xray client interoperability, RADIUS authentication,
hostapd-capable hardware, NIC remap and actual reboot/power-loss update/restore
tests remain external evidence requirements. No access to duck-dev-01 was made.

## 9. Safe Apply verdict

**FAIL for the complete public product contract.** The existing guarded controller
and state primitives are substantial, and the deadline defect is fixed locally.
The disconnected generic public path, disabled unsafe QoS path and lack of deployed
end-to-end recovery evidence prevent freeze. A Store commit is not Linux success.

## 10. API contract verdict

**FAIL.** Authentication/DTO defects were contained, but advertised operations,
collections, provider wiring, revisions and per-object permissions are not a stable
production contract. Schema changes made for secret safety must be reflected in
the final contract before freezing clients.

## 11. CLI contract verdict

**FAIL.** Credential transport is hardened. Several commands still target IPC URLs
on the public HTTP endpoint, and scripting/cancellation/exit-code parity is not
complete. Presence of command parsers/help is not working API parity.

## 12. Security verdict

**FAIL for production freeze.** Positive evidence: unprivileged API startup,
loopback/origin checks, Unix peer-UID boundary, private state, no-shell guarded
network execution, central identity checks and bounded secret-export primitives.
These do not establish per-object RBAC, secret-safe integration of every provider,
safe provisioning durability or safety of every optional privileged subsystem.
No blanket absence of injection, SSRF or log leakage is claimed for unconnected
future providers. No actual private key or subscription credential was exported.

## 13. Persistence/recovery verdict

**FAIL product-wide; core Store has positive local evidence.** Store locking,
bounded checksummed journal, synchronized replace, poisoned-state behavior and
existing recovery tests are useful. Generic configuration receipts, in-memory
update/provisioning state and first-run helpers do not inherit those guarantees
automatically. Power-loss/restart verification remains required on Linux.

## 14. Update/backup/restore verdict

**FAIL.** Parser/storage primitives were hardened, but durable activation,
source/schema compatibility, bounded/cancellable health checking, executable
rollback and protected selective portable restore remain software blockers.

## 15. UI-readiness verdict

**FAIL for starting production UI implementation against a frozen backend.** A UI
would currently need unsupported operations, missing object providers or guesses
about capability/transaction outcomes. The audit did not change or start the UI.
Existing observational endpoints can be useful, but that is not the requested
complete V1 backend/API/CLI freeze.

BACKEND AUDIT: FAIL

SAFE TO FREEZE BACKEND: NO

SAFE TO START UI IMPLEMENTATION: NO
